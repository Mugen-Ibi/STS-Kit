# 検証記録

この文書は初期構成の検証履歴です。現在の実測とテストは[PERFORMANCE.md](PERFORMANCE.md)、コードレビューは[REVIEW.md](REVIEW.md)を参照してください。

2026-09-27、Windows、AMD Ryzen 7 260、RTX 5070 Laptop 8GB。

追加音声モデルの調査・実測は[VOICE_MODELS.md](VOICE_MODELS.md)を参照。3モデルでの試聴、往復切り替え、Qwen/LFMでの音声対話、生成音声のGemmaによる再認識を確認済み。追加分を含む単体テストは14件成功。

LFMを選んだ状態で27秒入力・不正入力後の復帰・キャンセルも成功。27秒の反復質問から音声回答まで6.56秒。読み起こしの反復は従来どおり残るため、精度保証ではありません。

## 実モデルで確認したこと

- Gemma 4 E2B it Q4_0 + mmproj Q8_0を既存llama.cpp b10964 CUDA版でロード。
- Style-Bert-VITS2 JVNV F1 JP-Extra、日本語BERT、CUDA版PyTorchでWAV生成。
- 日本語のテキスト入力から返答音声を生成。
- LLMを通さずTTSで合成した既知の「日本の首都はどこですか」という音声を入力し、Gemmaで文字起こしした後に「日本の首都は東京です」と回答する音声を生成。別のASRエンジンは使用しない。
- 27秒の音声入力で同様の返答を確認。
- 不正な音声入力の拒否と、その後の正常な会話。生成途中のキャンセル。
- Web UIの表示、テキスト送信、返答表示と音声到着時間の表示。
- 入力検証・リサンプル・文分割の単体テスト6件。

## 計測例

|条件|最初の返答音声がサーバーから届くまで|生成全体|
|---|---:|---:|
|旧構成・CPU TTS、音声から直接回答、初回入力|7.83秒|8.84秒|
|最終構成・Gemma文字起こし→回答 + CUDA TTS、約1.9秒の質問音声|0.43秒|0.44秒|
|最終構成・27秒の反復質問音声|5.69秒|5.70秒|

独立した短文のTTS比較では、CPU約0.9〜1.4秒、CUDA約0.25〜0.40秒。GPU初回のカーネル準備は約16.7秒かかったため起動時に実行します。ブラウザでの自己紹介テストでは最初の音声到着0.81秒でした。

これらは少数の合成音声を使った動作試験です。モデルの回答長、音声内容、GPUを使う他アプリで時間は変わります。録音時間・実デバイスの再生遅延は含みません。全ランタイムの速度比較やマイクの実環境での認識精度評価はしていません。llama.cpp上流はGemma音声入力を実験的機能として扱っています。

音声から直接回答する初期構成では、首都について不正確な応答が出たため、最終構成では「Gemmaで文字起こし→同じGemmaで文章に回答」に変更しました。既知の質問は「日本の首都はどこです。」と認識し、正しく回答しました。ただし長い反復音声では文字起こしも繰り返しやすく、512トークン上限に達する例があります。これは会話品質・認識精度の保証ではありません。短く区切って話し、表示される認識結果を確認してください。

現在の再計測結果は`run/smoke-results.json`と`run/limits-results.json`に保存されます。

## 互換性対策

- PyPI公開版Style-Bert-VITS2は2.5.0を使用。GitHubの2.7.0とは区別。
- NumPy 1.26系とTransformers 4系を固定。PyTorchはBlackwell対応のCUDA 12.8版。
- 旧BERTのbin重みを、weights_only + mmapで読み出してsafetensorsへ変換。数値を量子化せず、ロード時のメモリ増大を回避。
- OpenJTalkの日本語パス制限を、ASCIIのTEMP配下へ辞書をコピーすることで回避。
- HTTPS証明書検証は無効にせず、ダウンロード時はWindowsの信頼済み証明書ストアを利用。
